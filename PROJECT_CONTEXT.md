# AntiLate — project context

Этот файл предназначен для продолжения работы в новом чате Codex. Перед любыми изменениями:

1. Полностью прочитать `AGENTS.md` и этот файл.
2. Проверить актуальные `App.tsx`, `package.json` и `app.json`.
3. Считать код главным источником истины: пользователь может менять значения между чатами.
4. Не начинать масштабный рефакторинг без отдельного запроса.

## Цель продукта

AntiLate — личное Android-приложение, которое помогает пользователю перестать опаздывать.

Главная идея: приложение работает не просто со временем встречи, а вычисляет:

- когда начать собираться;
- когда закончить одеваться и собирать вещи;
- когда выйти;
- когда пользователь уже начинает опаздывать.

Планируемый сценарий:

1. Пользователь создаёт встречу и выбирает сохранённое место.
2. Если место неизвестно, приложение спрашивает время в пути.
3. На основе времени встречи, дороги, сборов и буфера вычисляются дедлайны.
4. Приложение отправляет серию локальных уведомлений.
5. Пользователь отмечает, что начал собираться или вышел.
6. При пропуске дедлайна включается Late Mode.

Google Maps пока не нужен. Google Calendar будет добавлен после рабочего локального MVP.

## Технологии

- Expo SDK 54.
- React Native 0.81.
- React 19.
- TypeScript со `strict: true`.
- Expo Go используется для проверки на Android-телефоне.
- Manrope через `@expo-google-fonts/manrope`.
- `react-native-safe-area-context`.
- NativeWind 4 с Tailwind CSS для всех статических стилей интерфейса.
- AsyncStorage для локального хранения встреч.
- `@notifee/react-native` для точных локальных alarm-уведомлений, действий,
  full-screen intent и foreground service.
- Android application ID: `com.antilate.app`; после первой публикации его не
  менять, иначе Google Play будет считать сборку другим приложением.
- локальный Android Expo-модуль `modules/antilate-alarm` для проверки доступа
  к full-screen intent и повторяющейся вибрации через `VibrationEffect`.
- `expo-dev-client` для проверки нативной функциональности на телефоне;
  Expo Go продолжает работать как UI-режим, но alarm-функции в нём недоступны.
- `@react-native-community/datetimepicker`.
- React Navigation уже установлен, но навигация ещё не подключена.
- `expo-haptics` установлен для будущей тактильной обратной связи.

## Текущее состояние

Реализован локальный функциональный прототип:

- адаптивная безопасная зона;
- прокручиваемый главный экран;
- логотип AntiLate;
- кнопка добавления встречи;
- компактный чёрный блок следующего действия;
- блок следующего действия показывает четыре последовательных состояния:
  спокойное, зелёное предупреждение за 5 минут до сборов, жёлтые сборы и
  красное опоздание относительно времени выхода;
- пустое состояние для нового пользователя;
- создание, редактирование и удаление встреч;
- автоматический расчёт времени выхода;
- выбор даты в пределах текущего и следующего месяца;
- необязательный выбор группы встречи, включая явный вариант «Без группы»;
- управление группами через настройки: список изначально пуст, пользователь создаёт до 8 групп и задаёт каждой обязательное уникальное название и цвет;
- карточки групп используют компактную строку с выбором цвета, полем названия и
  удалением; счётчик и создание новой группы находятся в нижнем блоке действий;
- отдельный экран «О приложении» с описанием проекта, возможностями, информацией о локальном хранении данных и версией приложения;
- отдельный раздел шаблонов встреч в настройках: создание, редактирование,
  удаление и применение до 12 шаблонов;
- обычные шаблоны подставляют место, комментарий, время, длительность дороги и
  сборов, а также группу, но дата всегда остаётся самостоятельным выбором
  пользователя;
- повторяющиеся шаблоны хранят выбранные дни недели и время встречи, а на
  главном экране порождают только одну ближайшую вычисляемую карточку вместо
  создания множества отдельных встреч;
- системный фильтр «Расписание» появляется только при наличии активных
  повторяющихся шаблонов, не редактируется пользователем и не входит в лимит
  пользовательских групп;
- горизонтальные подписанные фильтры групп на главном экране с количеством встреч; порядок соответствует настройкам, а внутри любого фильтра встречи остаются отсортированы по времени выхода;
- единая палитра групп из 20 цветов в фиксированной сетке 4 на 5; цвет служит визуальным маркером и никогда не меняет пользовательское название группы;
- локальное сохранение и восстановление встреч через AsyncStorage;
- сбои чтения встреч, групп и шаблонов блокируют открытие обычных экранов и
  запись этих коллекций; вместо пустого списка появляется повторная загрузка;
- ошибки записи показываются в кастомном окне с повторным сохранением;
  изменения остаются в памяти, записи выполняются последовательно;
- локальное сохранение групп; старые вручную названные группы переносятся, а безымянные цветовые категории отбрасываются;
- автоматическое удаление прошедших встреч;
- одинаковые размеры карточек;
- адаптация для экранов уже 360 px;
- состояния нажатия и accessibility labels.
- единое кастомное подтверждение удаления встречи, шаблона или группы с
  контекстным пояснением и кнопками «Отмена» / «Удалить».
- отдельный экран настройки уведомлений с проверкой обычных уведомлений,
  точных будильников, полноэкранного доступа, notification channel и фоновой
  активности;
- в настройках уведомлений есть выключаемый по умолчанию «Короткий звук»:
  включённый сигнал использует однократный системный звук, не зацикливается и
  не обходит режим «Не беспокоить» или системную громкость;
- точные локальные сигналы начала сборов и времени выхода для обычных и
  повторяющихся встреч;
- полноэкранный alarm-экран с непрерывной вибрацией, действиями «ОК»,
  «Напомнить чуть позже» и «Я вышел»;
- отложенное напоминание рассчитывается как середина интервала между началом
  сборов и выходом и может быть создано только один раз;
- при изменении и удалении встречи старые сигналы отменяются, а расписание
  повторяющегося шаблона самостоятельно планирует следующую встречу;
- отдельные EAS-профили `development` и `preview`, причём `preview` создаёт APK.

Стартовых демонстрационных данных нет. При первом запуске пользователь видит
пустое состояние и подсказку создать встречу.

## Шаблоны встреч и умное расписание

Шаблоны хранятся локально в AsyncStorage под ключом
`@antilate/templates/v1`. Максимальное количество шаблонов — 12.

Обычный шаблон нужен для быстрого создания независимой встречи. При применении
он заполняет сохранённые данные формы, но не назначает дату: пользователь всегда
выбирает её для конкретной встречи сам и может изменить любое подставленное
значение до сохранения.

Повторяющийся шаблон дополнительно содержит активное расписание: дни недели и
обязательное время. Для него не сохраняется серия копий. Приложение вычисляет
только ближайшее подходящее событие, а после его завершения автоматически
показывает следующий день из расписания. Такая карточка:

- участвует в общей сортировке по времени выхода и в фильтре выбранной группы;
- сохраняет цвет пользовательской группы;
- отличается компактной меткой повторения рядом с датой, без дополнительной
  внутренней обводки;
- при нажатии открывает редактор исходного шаблона, а не редактор отдельной
  встречи.

При наличии хотя бы одного активного повторяющегося шаблона на главном экране
появляется умный системный фильтр «Расписание». Он показывает только вычисленные
повторяющиеся события, исчезает после отключения или удаления последнего
активного расписания и не занимает одно из восьми мест пользовательских групп.

## Текущая архитектура

Сайт приложения находится отдельно в `website`: React, Vite, TypeScript и
Tailwind CSS 4, собственный package-lock и статическая сборка. Секции находятся
в `website/src/sections`, компоненты — в `website/src/components`.
Секции сайта: первый экран, хронологический план встречи, возможности и FAQ.
Возможности показывают экраны групп, шаблонов и темы. Тему можно менять прямо
в телефоне; режим «Как в системе» отслеживает оформление браузера.
Кнопки скачивания используют локальный `AntiLate.apk` из корня проекта, если
он доступен во время запуска/сборки: Vite отдаёт его по `/downloads/AntiLate.apk`
и копирует в `website/dist/downloads`. APK исключён из Git. Без локального файла
используется последний GitHub Release, а `VITE_APK_URL` имеет приоритет;
токены на клиенте не используются. Корневая
TypeScript-конфигурация исключает `website`, чтобы DOM-типы и зависимости сайта
не участвовали в проверке React Native. Подробнее — `website/README.md`.

`App.tsx` отвечает только за загрузку шрифтов и корневые провайдеры. Код
разделён по ответственности:

- `src/screens` — отдельные экраны;
- `src/components` — переиспользуемые визуальные блоки;
- `src/hooks` — состояние и жизненный цикл встреч, групп и шаблонов;
- `src/storage` — версионированная работа с AsyncStorage, включая отдельное
  хранилище шаблонов;
- `collection-controller.ts` и `use-persisted-collection.ts` — общий жизненный
  цикл загрузки, последовательной записи и повторных попыток для трёх коллекций;
  успешная загрузка сама по себе не запускает запись. Синтаксически повреждённые
  данные, неверная структура и некорректные записи текущей схемы не заменяются
  пустой коллекцией. Нативные сигналы не перекрываются окном ошибки хранения.
- `src/utils` — чистые функции даты, времени, валидации и вычисления ближайшего
  повторения;
- `src/types` и `src/constants` — общие контракты и дизайн-данные.
- `src/notifications` — Android notification runtime, планирование, действия и
  синхронизация с локальными встречами;
- `modules/antilate-alarm` — небольшой Android-only Expo-модуль;
- `plugins/with-antilate-alarm.js` — manifest-настройки full-screen Activity и
  foreground service типа `specialUse`.

Функциональность шаблонов также разделена по слоям:

- тип и ограничения шаблона находятся в `src/types` и `src/constants`;
- нормализация, CRUD и локальная гидрация находятся в `src/storage` и
  `src/hooks`;
- вычисление ближайшей повторяющейся встречи не зависит от интерфейса и
  находится в `src/utils`;
- список и форма шаблонов находятся в `src/screens`, а выбор шаблона при
  создании встречи — в переиспользуемом компоненте из `src/components`;
- корневой координатор объединяет сохранённые встречи с вычисленными карточками
  расписания, но не записывает эти карточки в хранилище встреч.

Статические стили задаются через NativeWind. Inline-стили используются только
для вычисляемых значений safe area, динамических цветов тем и SVG-геометрии.

## Анимации интерфейса

- Общие длительности и easing находятся в `src/constants/motion.ts`.
- `src/components/motion` содержит общие компоненты: отклик на нажатие,
  появление и перемещение блоков, переход страниц, модальные окна и переключатель.
- Страницы переключаются с лёгким сдвигом и проявлением за 300 мс;
  при возвращении направление меняется. Alarm-экран проявляется за 140 мс.
- Нажатия: 100 мс на сжатие до 98.2%, 180 мс на возврат. Цвета выбранных
  фильтров и кнопок также меняются плавно. Обработчики действий не ждут анимации.
- Появление элементов занимает 260 мс, изменение раскладки — 240 мс;
  закрытие модальных окон — 140 мс. Карточки имеют стабильные ключи, поэтому
  ежесекундное обновление таймеров не запускает появление заново.
- `MotionProvider` учитывает системное уменьшение движения, в том числе
  изменение настройки во время работы приложения.
- Существующие NativeWind `active:scale`/`active:opacity` заменены общим
  `MotionPressable`; новые кнопки должны использовать его, чтобы избежать
  конфликтующих мгновенных и плавных эффектов.
- Всё реализовано на уже установленном Reanimated 4; нативная конфигурация
  и зависимости для этого изменения не менялись.

## Текущий дизайн

Иконка приложения подключена из утверждённого `design/icon/antilate-final-icon.svg`.
Используется его видимая монтажная область (бегун на коричневой подложке).
Готовые PNG находятся в `assets/antilate-*.png`: обычная иконка, прозрачный
Android adaptive foreground, монохромная маска бегуна и favicon. Фон adaptive
icon — `#FFFDFC`, старый `backgroundImage` удалён из конфигурации.
Генератор ассетов — `scripts/generate-app-icons.cjs`; он не нужен во время EAS Build.

Направление: premium minimal / Notion-inspired flat design, светлая и тёмная темы.

### Темы оформления

- «Настройки → Тема»: Светлая, Тёмная, Как в системе. По умолчанию — системная.
- Настройка сохраняется в AsyncStorage: `@antilate/appearance/v1`.
- Палитры и семантические цвета находятся в `src/constants/theme.ts`.
  `ThemeProvider` задаёт CSS-переменные NativeWind, системное оформление
  через Appearance и контраст статус-бара; изменение темы не размонтирует экраны.
- В тёмной теме используются графитовый фон, слегка более светлые поверхности,
  мягкие обводки и молочный текст. Цвета действий, текста на действиях и
  информационных карточек разделены, а не инвертируются одним цветом.
- Новые элементы используют семантические классы (`bg-paper`, `bg-canvas`,
  `text-ink`, `border-outline`, `bg-action`, `text-on-action`, `bg-feature`,
  `text-on-feature`) и `useTheme().colors` для динамических стилей/SVG.
- Цветные группы всегда сохраняют исходный HEX фона. Только контраст текста
  выбирается по яркости этого цвета, одинаково для обеих тем. «Без группы»
  адаптируется к оформлению. Для очень тёмных цветных карточек в тёмной теме
  усиливается обводка, не меняя сам цвет фона.
- `expo-system-ui` и `userInterfaceStyle: automatic` добавлены для Android;
  для полноценной проверки системного режима нужна новая development-сборка.
  Само приложение безопасно открывается и в предыдущей сборке: нативный модуль
  используется опционально. EAS/Gradle в рамках этой UI-задачи не запускались.

Основные решения:

- тёплый светлый фон;
- Manrope;
- единая типографическая шкала: большой текст `20` с начертанием ExtraBold,
  средний `12` с обычным и ExtraBold начертаниями и маленький `10` с
  начертанием Manrope Regular; отдельные размеры не используются для текстового
  содержимого, только для графических символов кнопок;
- чёрно-белая база;
- глубокий бордовый только для активного события;
- без градиентов и декоративных теней;
- толстые, но аккуратные контуры;
- максимум две строки для длинного названия места;
- спокойный вторичный текст;
- одинаковая геометрия активных и обычных карточек.
- только на главном экране закреплён навигационный островок высотой `56`:
  настройки слева, кликабельный логотип AntiLate по центру и добавление встречи
  справа; при прокрутке вниз островок плавно сужается на `15%`, не деформируя
  содержимое, и возвращает полную ширину в верхней позиции;
- подписи полей формы используют ExtraBold `12` и сдвинуты внутрь на `16`,
  включая подписи над тремя компактными полями;
- заголовки «ДАТА» и «ГРУППА» расположены над скруглёнными контейнерами и
  выровнены с полноширинными подписями формы.
- введённые значения места и комментария используют обычное начертание `12`,
  совпадающее по размеру с их подписями; числовые значения компактных полей
  всегда сохраняют размер `20`.
- на внутренних экранах нет дополнительных подзаголовков: основной заголовок
  использует ExtraBold `20`, выровнен с кнопкой назад и начинается на одной
  вертикальной линии с внешним краем форм и карточек; содержимое начинается
  сразу после шапки.
- карточки управления группами повторяют геометрию карточек шаблонов, но
  остаются инструментальными: цвет, название и удаление находятся в одной
  строке, а палитра раскрывается внутри карточки;
- экран настроек использует ту же шкалу: заголовок `20` ExtraBold, названия
  разделов `12` ExtraBold и пояснения `10` Regular; отдельного подзаголовка под
  словом «Настройки» нет.

- тёмный цвет границы активной карточки: `#701137`.

Нижняя строка карточки построена без badge/chip:

- слева: подпись «Выход» и время выхода;
- справа: подпись «В дороге» и продолжительность пути;
- подписи используют средний размер Regular `12`, а значения времени —
  ExtraBold `12`; название места и главное время прибытия используют ExtraBold
  `20`; комментарий использует Regular `10`, показывается в одну строку и при
  нехватке места заканчивается многоточием.

Шапка, countdown и карточки находятся в одном общем контейнере и используют один `PAGE_GUTTER`. Не добавлять отдельные внешние горизонтальные отступы этим секциям.

## Важные ограничения рабочего процесса

Для обычных UI-изменений:

```bash
npx tsc --noEmit
```

Не запускать без прямого запроса пользователя:

- `expo export`;
- EAS Build;
- Gradle/Android build;
- другие долгие сборки;
- новый долгоживущий Expo/Metro-процесс.

Alarm-уведомления нельзя проверять в Expo Go. Для них использовать
development APK и запуск Metro командой `npm run start:dev-client`. Перед
первой важной встречей открыть «Настройки → Уведомления», включить обязательные
доступы и запустить тест через 3 секунды.

Если команда не выводит ничего 90 секунд:

1. остановить её;
2. проверить причину;
3. сообщить пользователю.

Делать небольшие контролируемые изменения и показывать результат перед продолжением.

Не перезаписывать пользовательские изменения и не предполагать, что значения из этого файла всегда новее кода.

## Рекомендуемый порядок разработки MVP

### 1. Разделить проект по минимальной структуре — выполнено

Не делать большой рефакторинг. Постепенно вынести:

- типы;
- функции расчёта времени;
- хранение;
- экраны;
- переиспользуемую карточку события.

### 2. Настройки пользователя

Добавить:

- время на одежду;
- время на сбор вещей;
- базовый запас;
- строгость уведомлений.

### 3. Сохранённые места

CRUD для места:

- название;
- алиасы;
- время в пути;
- предпочтительный способ передвижения на будущее.

### 4. Quick Plan

Подключить кнопку `+` и создать встречу:

- место;
- описание;
- дата и время;
- ручное время дороги для нового места;
- проверка, что время находится в будущем.

### 5. Локальное хранение

Хранить через AsyncStorage:

- настройки;
- места;
- запланированные встречи;
- статусы встреч.

Добавить версионирование схемы хранилища, чтобы будущие обновления не ломали сохранённые данные.

### 6. Расчёты

Вынести чистые функции:

```text
leaveAt = eventTime - travelMinutes
startPrepAt = leaveAt - dressMinutes - bagMinutes - bufferMinutes
firstWarningAt = startPrepAt - 5 minutes
```

Обязательно покрыть граничные случаи:

- переход через полночь;
- прошедшая встреча;
- изменённое время встречи;
- очень короткое время до события.

### 7. Подключить главный экран к реальным данным

- сортировка будущих событий;
- удаление прошедших;
- живой countdown;
- автоматическое определение активного события;
- пустое состояние;
- открытие карточки встречи.

### 8. Локальные уведомления

Запланировать уведомления:

- первое предупреждение;
- начало сборов;
- проверка вещей;
- время выхода;
- начало опоздания.

При изменении или удалении встречи старые уведомления должны отменяться.

### 9. Статусы и Late Mode

Статусы:

- `planned`;
- `preparing`;
- `should_leave`;
- `left`;
- `late`;
- `arrived`;
- `ignored`.

Действия:

- «Я начал собираться»;
- «Я вышел»;
- «Я опаздываю»;
- таймер опоздания;
- шаблон сообщения о задержке.

### 10. Только после локального MVP

- Google Calendar OAuth и импорт событий;
- сопоставление location с сохранёнными местами;
- Google Maps/Routes при реальной необходимости;
- адаптивный персональный буфер на основе истории.
